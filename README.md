## 2. Architecture at a glance · 架构一览

```
Browser ──HTTPS──> reverse proxy ──> web_dashboard.py (FastAPI :8080)
                                          │
                                          ├─ user_session cookie (HMAC)  ← sole identity channel
                                          ├─ dashboard_routes/*.py        (JSON API)
                                          ├─ PostgreSQL (public schema)   (users, bets, points, copy_tasks…)
                                          └─ Privy (embedded wallets, MFA) + Polymarket CLOB v2

Browser ──HTTPS──> admin-v3 (:8081) ──> routes_admin.py ──> PostgreSQL (admin_v3 schema, fully isolated)
```

The user site is a single FastAPI process; the Admin V3 console (when licensed) runs
separately on `:8081` with an isolated `admin_v3` schema.

用户站是单个 FastAPI 进程；Admin V3 后台（获得授权后）在 `:8081` 独立运行，使用隔离的
`admin_v3` schema。

**Identity model · 身份模型**

`user_session` is an HMAC-signed cookie derived from `USER_SESSION_SECRET`. Privy access
tokens are verified server-side against the Privy JWKS public key
(`config/privy_verification_key.pem`). A user's wallet is resolved **only** from the
Privy API response — never from client-supplied data.

`user_session` 是由 `USER_SESSION_SECRET` 派生的 HMAC 签名 Cookie。Privy 访问令牌在服务端
依据 Privy JWKS 公钥（`config/privy_verification_key.pem`）校验。用户钱包**仅**从 Privy
API 响应解析——绝不信任客户端提交的数据。

无需 Python 工具链——一条 `docker compose up` 即可同时拉起用户站与 PostgreSQL 数据库：

| 服务 · Service | 镜像 · Image | 用途 · Purpose |

## 8. Security · 安全

Please read [SECURITY.md](./SECURITY.md). Highlights:
请先阅读 [SECURITY.md](./SECURITY.md)。要点：

- `user_session` is the **only** user identity channel; the legacy `DASHBOARD_KEY`
  / TOTP / `?key=` bypasses are removed.
  `user_session` 是**唯一**用户身份通道；旧的 `DASHBOARD_KEY` / TOTP / `?key=` 旁路均已移除。
- Identity is derived exclusively from the Privy API response, never from the request body.
  身份**仅**从 Privy API 响应解析，绝不来自请求体。
- Login MFA is **server-side TOTP** (Google Authenticator compatible); the `mfa_verified`
  marker is HMAC-signed and the client `mfa_verified` boolean is ignored.
  登录 MFA 是**服务端 TOTP**（兼容 Google Authenticator）；`mfa_verified` 标记经 HMAC 签名，
  客户端 `mfa_verified` 布尔值被忽略。
- Admin console routes are all gated by `Depends(current_admin)` / `require_permission`.
  后台路由全部由 `Depends(current_admin)` / `require_permission` 把关。
- All SQL uses bound parameters; identifiers come from fixed whitelists.
  所有 SQL 使用绑定参数；标识符来自固定白名单。
- Secrets are read from the environment only.
  密钥仅从环境变量读取。

Report vulnerabilities privately — see [SECURITY.md](./SECURITY.md).
漏洞请私下报告——见 [SECURITY.md](./SECURITY.md)。

## 10. Obtaining the Admin V3 console · 获取 Admin V3 后台

The operator console is **not** part of this distribution. It is offered separately,
under its own private licence — it is **not** covered by this repository's Apache-2.0
licence, and this repository grants no rights to it.
运营后台**不**包含在本发行版中。它以独立私有许可另行提供——**不受**本仓库 Apache-2.0 许可
覆盖，本仓库也不授予对其的任何权利。

**How to get it**, in order of preference · **获取方式**（按推荐顺序）：

1. **Direct contact (recommended).** Message the author on X/Twitter
   [@VeyraTrade](https://x.com/VeyraTrade) and describe your operating scenario and
   scale. You'll receive the access method and cooperation terms. This is the first step
   toward long-term cooperation and setup support.
   **直接联系（推荐）。** 通过 X/Twitter [@VeyraTrade](https://x.com/VeyraTrade) 联系作者，
   说明你的运营场景与规模，即可获得后台获取方式与合作条件。这是建立长期合作与技术支持的第一步。
2. **Managed hosting / setup service.** Teams that prefer not to self-host can buy a paid
   deployment; the admin console is included with it.
   **托管 / 代部署服务。** 不想自托管的团队可购买付费部署，后台随托管一并提供。
3. **Sponsorship.** Sponsor the project on GitHub Sponsors / Polar to support ongoing
   development. Sponsorship is a thank-you, not a licence — access terms are agreed
   directly with the author.
   **赞助（Sponsor）。** 通过 GitHub Sponsors / Polar 赞助项目，支持持续开发。赞助是回馈而非
   许可——后台权限以与作者沟通为准。

> The admin console moves real money and can write `.env`. It is handed out with a written
> licence and a support channel rather than posted publicly, so that operators get setup
> help and the author keeps a record of who holds a copy.
>
> 后台会操作真实资金并可写入 `.env`。它以书面许可 + 支持渠道的方式交付而非公开张贴，以便
> 运营方获得部署帮助、作者保留副本持有人记录。

Reusing the strategy engine, the API or the front-end in your own product is welcome —
subject to Apache-2.0. Reusing the admin console is a separate conversation.
复用策略引擎、API 或前端到你的产品中是被欢迎的——遵循 Apache-2.0。复用后台则是另一回事。
